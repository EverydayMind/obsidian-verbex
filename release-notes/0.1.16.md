## What's new

- **Recommended settings per model.** The chat model settings window now shows a card for models with checked settings (Gemma 4 31B, GPT-5.4 nano, Inkling 2 mini, Qwen 3.8 Flash and Solar Pro 4): the current value next to the recommended one, the reason, the evidence and the date it was checked. *Fill recommended values* fills the form only; nothing is saved until you save. Model instructions are appended after your own text. Warnings appear as you edit when a value is known to be ignored or harmful for that model; they never block saving. The add-model window marks known models with a badge.
- **Diagnostics for other models.** For a model without a profile, *Run diagnostics* sends a few small requests (it costs a few API calls; on OpenRouter it also reads the endpoint list): a structured tool call, tool-turn reasoning tokens at default, none and low, OpenRouter `reasoning.max_tokens` 256, the response time of a short request without tools, and the OpenRouter endpoints with their quantization and `tool_choice` support. The result is a table of facts and rule-based suggestions that can fill the form. It does not judge answer quality. Closing the window stops it.
- **New per-model settings.** OpenRouter provider order and fallbacks, the reasoning object (`max_tokens`, effort, enabled) for OpenRouter, reasoning effort and a time limit for the Skill/Workflow selection call (on timeout Verbex falls back to keyword selection), and model instructions added to the end of the system prompt. Models without these settings send the same requests as before.
- **Fixes.** `restore_last_change` states more clearly what was restored and what was left out. Grouped `query_notes` results include the group total, and no total when nothing matched. The task owner in an owner table prefers the linked name.

No Verbex tool definition changed, so plugin approvals stay valid.
