## What's new

Verbex now works with more of Obsidian's core plugins, and reads Bases the way Obsidian shows them.

- **Bases through Obsidian's own engine.** The agent evaluates a base with the Bases core plugin, so formulas, grouping, `this`, sorting and non-Markdown files give the same rows you see in Obsidian. Earlier versions used a simplified evaluator that left formula columns empty, ignored grouping and refused `this`; it remains as a fallback when Bases is turned off. AI-private files are left out of base results.
- **Daily notes.** A new tool finds the daily note for a date or a range from your Daily notes settings, and creates today's note from your daily note template, placing new lines under the heading you name or, for tasks, in the template's empty task line.
- **Templates.** A new tool lists your templates and creates a note from one, filling in `{{title}}`, `{{date}}` and `{{time}}` the way the Templates plugin does. You can give the date and time to use.
- **Bookmarks.** A new tool lists what you have bookmarked.
- **Canvas.** New tools describe a canvas (groups, cards, connections, missing files) and add, edit or remove cards and connections without rewriting the whole file.
- **Search syntax.** Vault queries accept `path:`, `file:`, `tag:` and `-` exclusion together with quotes and `OR`. Other Obsidian search operators are refused with a list of what is supported, instead of silently matching nothing.
- **Counts from tools.** The note outline now reports the body's character and word counts (frontmatter excluded). The link graph tool reports how many notes link to a note and can break them down by a property such as `type`. The active note's link counts and body character counts are given to the agent as facts.
- **Open Obsidian views.** When you ask, the agent opens the graph view, a local graph, a search, the backlinks, outline, tags or bookmarks pane, or a note.

## Fixes

- **Edits through a bare file name.** Asking to change a file by its name alone (for example a canvas outside the vault root) could read one file and propose the change for another, and the change then failed with a conflict. Editing tools now take the exact path; when a file with that name exists elsewhere, the agent is told the full path and calls again.
- **Broken `.base` and `.canvas` files.** A `.base` with a YAML or expression error, or a canvas with a connection to a missing card, is refused before it is proposed. These files are approved as a whole, and after a `.base` is saved the agent reports how many rows each view shows.

## Compatibility

- Settings, conversations, checkpoints and indexes are unchanged.
- Bases shows one more view type, "Verbex AI reader". Verbex uses it to read bases; if you choose it in a base, switch back to a table. A base saved with that view type shows as an unknown type when Verbex is disabled.
- Vault queries that searched for the literal text `path:`, `file:` or `tag:` now use them as operators. A query cursor from an earlier version asks to start the query again.
- If you turn the Bases core plugin off and on again, Obsidian stops rendering `base` code blocks until it is restarted; until then Verbex reads bases with the simpler evaluator.
- Going back to 0.2.1 is safe; the files Verbex created are ordinary notes, bases and canvases.
