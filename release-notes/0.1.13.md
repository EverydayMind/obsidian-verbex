## What's new

- **Collecting every matching line.** A new line mode for vault queries gathers each matching line, such as every statement by one speaker across meeting notes, page by page until the whole set is delivered. The agent is told to keep fetching until delivery is complete before it answers, and note mode now also returns every matching note in pages instead of a sample.
- **Search scope and tool clean-up.** Vault search can be limited to a folder, semantic candidates are part of vault search instead of a separate tool, and tools that return only a sample say so on their first line. Requests that ask to collect what someone mentioned or said are recognized more reliably.
- **A coverage check before the final answer.** When the agent is about to answer while a collection query in the same turn is still unfinished, it receives a short factual notice with the query, how many notes were scanned and the next page, and is asked to continue or rewrite its whole answer. If it fetches more and stops again before the end, the notice is repeated, up to three times per turn and only while progress is being made.
- **Coverage report under the answer.** After an answer built from an exhaustive query, Verbex rescans the same targets on its own and shows a collapsed card with the scope and how many notes and lines matched. The card is not sent to the model, and you can export the full table to a new note with a button (the new note is created only after you approve it).
- **Gathered context is labelled as a selection.** Context that Verbex collects automatically now says it is a selection, not a full sweep, and links the notes it came from.
- **Safer edits.** Writes that remove existing lines always ask for approval and show the reason in the interface language. Edit blocks with omission markers ("…") are handled before they are applied, headings inside code fences no longer confuse applying to a section, and when you reject a change the agent is told so and does not propose the same change again; earlier rejections of the same file are shown on the next approval.
- **Tool calls without a preamble.** The agent is asked to make the tool call in the same response instead of first explaining what it is about to do, which kept some models from stopping before the call.
- **Report drafts.** Drafts based on a sample report no longer copy the sample's own sections, and a renamed draft is used in place instead of being rewritten.
- **Setup help for OpenAI-compatible servers.** When an OpenAI-compatible server returns 404, the error now shows the address that was called and explains the Base URL (`/v1`) and Responses API settings.

No companion plugin changed its tools, so no new approval is needed.
